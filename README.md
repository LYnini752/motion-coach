# Motion Coach · 运动姿态观察室

[简体中文](README.md) | [English](README.en.md)

输入一段录像，输出 **骨架视频、二维关节角度、动作变化曲线、关键帧候选和可下载的数据**。支持选择网球、高尔夫或滑雪；使用 MediaPipe Pose Landmarker 在本机处理。

首版是可追溯的运动学观察工具。它不从普通录像推断真实力量、足底压力、雪板承重或伤病风险，也不把关键帧极值包装成专业动作评分。

## 能做什么

| 模式 | 观察重点 | 关键帧候选 |
|---|---|---|
| 网球 | 肘角、躯干倾角、惯用侧手腕相对移动 | 手腕移动峰值及其前后约 0.3 秒、膝角变化峰值 |
| 高尔夫 | 肘角、髋角、躯干投影变化 | 手腕移动峰值、膝角变化峰值、关节角极值 |
| 滑雪 | 左右膝角与变化时序、躯干投影 | 左右膝角最小值、膝角变化速度峰值 |

运动类型由使用者选择，不会自动识别某个动作是否发生。相邻峰值的先后顺序是画面测量，不能据此断言真实发力顺序。没有球拍、球杆、球或雪板跟踪，也没有自动击球时刻检测。

## 本地运行

需要 Python 3.11–3.13。macOS Apple Silicon 已跑通模型视频测试；其他平台的状态见 [VALIDATION.md](VALIDATION.md)。

在仓库目录运行：

```bash
git clone https://github.com/LYnini752/motion-coach.git
cd motion-coach
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python cli.py --doctor
python app.py
```

打开 <http://127.0.0.1:7864>，上传录像，选择运动和惯用侧，点击“开始分析”。第一次会从 Google 官方地址下载约 5.5 MB 的姿态模型，并校验固定 SHA-256；模型缓存齐全后可离线分析。

```bash
python cli.py '/path/to/tennis.mp4' --sport tennis --side right --fps 30
python cli.py '/path/to/golf.mov' --sport golf --view side
python cli.py '/path/to/skiing.mp4' --sport skiing --fps 15
```

可选环境变量：`PORT` 修改网页端口；`POSE_MODEL_PATH` 指向自备的兼容 `.task` 模型；`FFMPEG_BINARY` 指定 FFmpeg。默认使用系统 FFmpeg，或 imageio-ffmpeg 提供的二进制。安装脚本和文件锁针对 macOS/Linux，Windows 原生尚未验证。

## 人物区域裁剪

人物较小时，展开“拍摄与分析设置”，填写左、上、宽、高的画面百分比，再点“预览人物区域”。绿色框基于自动旋转后的第一帧；必须自行确认整段动作全身都在框内。裁剪可以帮助模型聚焦，但不能补回原片缺失的像素细节。

```bash
python cli.py video.mp4 --sport golf --crop 25 40 35 35
```

此例分析横向 25%–60%、纵向 40%–75% 的范围。报告保存裁剪参数；关键点坐标以裁剪、旋转和像素比例校正后的画面为准。默认保留全画面。

## 拍摄与使用

- 使用单人、全身清晰、无剪辑的片段；尽量固定机位。模型检测到多人的帧会跳过，但也可能漏检其他人；请先确认实际是单人录像。程序不做人脸识别或身份追踪。
- 每次最好只放一个挥拍、挥杆或一个短滑雪片段，便于回看。视频最多 500 MB，只分析前 60 秒。
- 默认分析 15 帧/秒；快速动作可选择 30 帧/秒。高帧率输入会按真实时间轴重采样，低帧率输入不会凭空增加可用运动信息。
- 时间和速度按视频播放时间轴计算，慢动作或加速视频没有自动还原为真实动作速度；不要把不同播放倍率的速度直接比较。
- 前后两次对比应使用相同机位、镜头和距离。画面中的角度不是校准后的三维角度。
- 提高置信度阈值会减少误测，但也会产生更多空值。有效检测不足 50% 时，报告明确提示重新拍摄或调整设置。

手机旋转信息和非方形像素比例由 FFmpeg 预处理；分析视频会统一为固定帧率，最长边不超过 960 像素，导出 H.264 MP4。输出不保留音轨。

## 指标如何计算

1. MediaPipe 输出 33 个关键点。本程序只使用二维坐标、可见度和存在置信度。
2. 按实际宽高还原像素坐标，再计算肘、膝、髋的三点夹角，避免把非正方形画面当成正方形。
3. 躯干倾角相对于画面竖直方向，正负号表示画面左右，不自动代表身体前倾/后仰。
4. 手腕位置减去髋中心，再除以投影躯干长度；相邻帧位移除以时间得到“躯干长度/秒”。它不是米/秒或球拍速度。
5. 膝角变化率使用度/秒。速度曲线取连续三个样本的中位数；缺失值保持缺失，不跨遮挡插值。
6. 关键帧要求对应指标至少有 50% 的可用样本且不少于 5 帧。为抑制静止检测抖动，手腕峰值要求 10%–90% 分位的相对位置范围达到 0.1 个躯干长度，膝角速度峰值要求角度范围达到 5°。这些是显示规则，不是技术优劣或医学阈值。
7. 若可见关键点包围区域的中位像素高度不足 120，隐藏所有关键帧候选并提示重新拍摄。这是首版保守的显示规则，未做阈值标定；高于阈值也不保证跟踪准确。

肩髋连线的画面夹角也保存在原始报告中，但不能代替真实转体角度或高尔夫 X-factor。没有标定、身体质量与外部作用力测量时，不计算关节力矩或真实发力大小。

## 输出与隐私

每次分析写入 `.local/runs/<任务编号>/`：

- `annotated.mp4`：带骨架的视频；`motion.png`：角度与动作变化曲线。
- `keyframe_*.jpg`：候选帧，可结合原片回看。
- `report.json`：完整指标、覆盖率、模型散列、方法与限制。
- `measurements.csv`：每帧测量；空单元格表示缺失，不是零。
- `landmarks.jsonl`：单人检测帧的二维关键点，用于复核。
- `summary.md`：中文摘要；`status.json` 与 `process.log`：任务状态和日志。

本应用使用本机模型，没有远程视频推理接口。网页仅监听本机，Gradio 统计上报已关闭。首次下载模型/依赖需要联网。

**依赖联网行为：**实测 MediaPipe 0.10.35 出现向 Clearcut 发送运行统计的日志；[上游问题记录](https://github.com/google-ai-edge/mediapipe/issues/6291)也报告了该行为。本项目尚未确认全部请求载荷或受支持的关闭开关，不承诺所有依赖零联网。严格离线使用时，请先完成依赖与模型下载，再在无外网连接的环境运行。输入上传缓存可能保留在系统临时目录；分析结果保留在本机，不自动删除。确认不再需要后可用文件管理器删除对应任务目录。模型和个人视频不会进入 Git 提交。

## 界面

黑色与荧光绿色的本地分析工作台：左侧上传录像和设置，右侧切换原片与骨架回放，下方分栏查看观察摘要、角度曲线、关键帧和导出记录。上传新录像会清空上一份结果，分析成功后自动打开骨架回放。图表与骨架使用统一配色；不显示未经验证的动作评分或发力评分。
